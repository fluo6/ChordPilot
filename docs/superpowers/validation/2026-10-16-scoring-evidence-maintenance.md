# Scoring evidence and maintenance check

Local Study and Beat Detail now show a twelve-note **Pitch-class input to chord scorer** plot below the frequency spectrum. Teal bars are normalized evidence from the selected harmonic source (usually accompaniment) after selected tail/overtone processing; amber bars are the actual pitch-class blend passed to each candidate scorer. The Bass contribution appears at its detected pitch class only when confidence is at least 0.62, with weight `0.3 × min(1, bass confidence)`. Separate root/inversion, essential-tone, key and continuity terms still affect the chosen chord, so the bars are not a full explanation of the final rank or an FFT of mixed audio. Old saved results do not have this plot until reanalysis. Algorithm versions advance to `sub-bar-v21` and `local-study-v27` so cached results are refreshed.

`studyDetectionSettings` now treats Simplify Chords as display-only for all explicit Local Study versions from v3 onward, including the current v27. It retains v2's historical input identity. Missing overtone settings keep the historical pre-v10 zero default; v10 onward use the current 0.5 default. The UI comparison and source spectra remain independent of the new plot.

Two formerly excluded JavaScript tests now run on Windows: environment defaults follow platform Python selection and the installed bundled FFmpeg path, while the smoke cleanup failure injection recognizes `smoke.wav` with either path separator. An unqualified `npm test` passed with **315 JavaScript** and **201 Python** tests outside the filesystem sandbox; the Windows temporary rename tests and SciPy import require that access. The reference comparison still matches all 83 checked local windows (Hero 17/20 roots; Virtual Insanity 7/13; Gravity 12/16; Overjoyed 19/21; September 5/13), with function and exact counts unchanged. This is regression preservation, not a new accuracy gain.

Voicing snapshot cost was measured separately on the existing Hero Other stem with `scripts/testing/voicing-performance.py`: for 2, 20 and 60 seconds of audio, snapshot processing took 0.022, 0.099 and 0.100 seconds respectively on this machine; serialized snapshots occupied 411, 2,406 and 2,498 bytes. Long intervals hit the 64-snapshot cap. This measures the isolated snapshot stage, excluding Demucs, audio loading, other analysis and UI rendering. The cap samples a long passage rather than transcribing every instant; keep it until independently checked voicing labels justify more coverage.

The [reference run guide](reference-runs.md) documents media, settings, commands, provenance and limitations. README now describes implemented high-quality stem analysis instead of the old plan. Historical reports with superseded vocabulary findings have dated notices linking to the later implementation and current baseline.
